BLAKE2b epochs

The difficulty epochs of each Bitcoin Knots BLAKE2b chain since the split from Bitcoin Core, one headers file per epoch. A complete epoch is sealed once and never changes. Verify any epoch here: the page fetches its file and runs every header rule in this tab. Unlinked experiment.

how this works

An epoch is 2,016 blocks, the difficulty retarget interval. data/epochs/<net>/index.json lists every epoch from the one containing the split; data/epochs/<net>/<n>.bin holds that epoch's headers in height order, 80 bytes before the BLAKE2b fork and 164 from it. The index also carries the eleven headers before each epoch and whatever earlier headers the difficulty rules need, so an epoch can be verified on its own. Sealed epochs are written once; their SHA-256 is the thing to compare across hosts. The current epoch is rewritten as blocks arrive.

Verify fetches the file, checks its SHA-256 against the index, decodes every header, and runs the header rules over the epoch with the engine: proof of work, linkage, difficulty with the fork adjustment, median time past, future time, version, timewarp, and the fork rules. Engine: bitcoin-desktop/schema@v0.0.25 via jsDelivr with the knots-blake2b overlay. Nothing here is trusted: a wrong file fails on arrival.
